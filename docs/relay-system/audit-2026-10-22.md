## Result and scope

The implementation is a reusable, deterministic relay interpreter with shared
continuations. It is not a brute-force auction solver. Most programmed tables
agree with the applicable source within their published practice restrictions,
but the sources and implementation are **not completely consistent or complete**.
The most concrete error is a diamond keycard answer that should bypass 3NT.
There is also a reproduced discrepancy between artificial-3NT pass handling
and the maintenance guide. Several normal continuations remain outside the
trainer; these matter before extreme shapes.

This audit compares the retained main Word notes, separate rebid Word notes,
July email transcription and subsequent partnership clarifications against all
eight programmed families. Sections with no executable family are inventoried
as coverage gaps, not claimed as verified implementations. Carding/defence notes
are outside the current uncontested bidder.

The baseline is commit `3d0a540324fb128f6133d03f09d6c746e1c072ac`.
Other UI/bid-preview edits appeared in the shared working tree during the audit;
they were left untouched. This report records the baseline bidding rules and
read-only reproductions, not certification of those concurrent UI changes.
No bidding meanings or source originals were changed by this audit.

## A. Reproduced implementation discrepancies

### A1 — Diamond SKC after 1C–1S–2M fails to bypass answer 3NT

**Resolved on 20 November.** Both routes now share the P0425 reply table, including 3NT with two diamonds. The original finding is retained below.

**Finding on 22 October.** P0422–P0425 covers both the
direct `1C–1S–2M` route and `1C–1S–2C–2D–2M`. Responder 3D shows five diamonds.
Opener with three diamonds answers diamond SKC **bypassing 3NT**; with two
diamonds, opener bids 3NT to play.

The direct profiles `club-1s-2h-keycard` and `club-1s-2s-keycard` admit only
three diamonds but call the generic consecutive keycard helper. The strong
2C–2D profile correctly uses an explicit ladder skipping 3NT. Consequently the
same documented continuation has different keycard meanings in the two paths.

| Diamond SKC response after 3D | Required by P0425 | Direct profile currently |
|---|---|---|
| Void | 3H | 3H |
| 0/3 | 3S | 3S |
| 1/4 | 4C | **3NT** |
| 2/5 without Q | 4D | **4C** |
| 2/5 with Q | 4H | **4D** |

Evidence: [club-profiles.js](../../website/relay/club-profiles.js),
`clubKnownShortage`, actions 3C/3D; compare
[strong-club-profiles.js](../../website/relay/strong-club-profiles.js),
`major-shortage`, and `explicitKeycardResponses` in
[source-utils.js](../../website/relay/source-utils.js).

The doubleton-diamond branch is a separate disclosed omission in the direct
profile. Excluding that branch does not justify assigning its reserved 3NT to
keycards. Correction should reuse the explicit source ladder and test both
routes against the same expected calls.

### A2 — Some artificial 3NT answers can be passed

**Resolved by Josh, 11 November 2026:** the asker controls the final contract
and may pass an artificial relay answer. The reordering notes R0105–R0108
explain the teller’s strength escape beyond the normal ladder. The program’s
permission to pass was not the error; the contrary maintenance invariant was.
The original dated reproduction below is retained as history. See
[questions for Markey](questions-for-markey.md), Q1.

**High priority; confirmed program/documentation discrepancy, forcing agreement
needs confirmation.** A normal generated deal gives:

`1D–1S–2C–2H–2NT–3C–3NT`

The last call means **2 or 5 keycards without the trump queen**, with phase
`post-keycard`. The engine offers Pass and accepts it as 3NT by North.
`familyActions` in [core.js](../../website/relay/core.js) permits Pass at 3NT
unless `threeNTToPlay` is explicitly false. Several club/minor/Dappleton states
leave that flag undefined. The maintenance guide's invariant 7 says artificial
3NT answers must not become passable unless the branch explicitly permits it.

The email's “3NT by responder is always to play” establishes the asker's 3NT
meaning; it does not explicitly settle passing an artificial **opener** 3NT
answer after keycard. Some reordered single-suit replies intentionally land on
playable game and must retain that escape (R0105–R0108).

**Clarify:** should ordinary artificial keycard/shape 3NT answers be forcing,
with only explicitly designated offers/strength escapes passable? Or is choosing
3NT after such an answer an intended option? Then make the code and guide agree
without removing the explicit reordered exceptions.

### A3 — Strong-club 16+ clarification is not propagated to Baron

**Scope question, not a proved wrong reply.** The strong 2C–2D resolver admits
16+ unbalanced hands, following the user clarification. The same
`1C–1S–2C` prefix in `club-1s-2c-baron` still admits unbalanced hands only at
17–19 and labels the prefix 17+. It also caps balanced hands at 19, while the
resolver includes 20 under its published practice cap.

P0382/P0402/P0421 have the older 17+ wording. The question is whether the 16+
correction applies to the **2C rebid generally**, or only the specified 2D
resolver exercise. If general, Baron filters and labels need updating too.
The upper caps are practice restrictions, not automatically another error.

## F. Engineering and validation findings

- **Saved rules can be stale.** [progress.js](../../website/relay/progress.js)
  validates snapshot format, cards and stored constraints, but has no bidding-rule
  revision fingerprint or replay migration. An old valid save can retain obsolete
  ranges or pending answer ladders after code changes. This already matters for
  the corrected 11-count range. Add rule-version invalidation or reconstruction.
- **Forcing state is implicit.** A2 shows why playable/forcing/optional status
  should be explicit rather than inferred from a contract-shaped call and an
  absent flag. This will also help implement R0192 correctly.
- **Entry coverage is not global coverage.** Profiles have public HCP/shape
  filters. Tests should include source-authored hands just outside those filters,
  reporting “not yet supported” rather than making their absence look like a
  system rule. No full opening/response classifier currently supplies this check.
- **Semantic fixtures need more cross-entry checks.** Shared code reduces copies,
  but A1 arose where one source exception used a generic helper in one profile
  and an explicit table in another. Add common expected-ladder fixtures for
  source-equivalent continuations and the agreed 3NT forcing rules.

### Reproducing the two concrete discrepancies

Run from the repository root with Node available. This is a diagnostic, not an
expected-passing regression test:

```js
// node --input-type=module
import {
  createPractice, applyBid, availableActions, matchesConstraints,
  getPracticeProfile,
} from './website/relay/core.js';

const profileId = 'club-1s-2h-keycard';
const profile = getPracticeProfile(profileId);
let club = {
  ...createPractice({ profileId, seed: 'source-audit' }),
  partnerHand: 'S2 HA HK H2 DJ D7 D6 CK CQ CJ CT C9 C8'.split(' '),
  playerHand: 'SA SK SQ HJ DT D9 D8 D5 D4 CA C7 C6 C5'.split(' '),
};
console.assert(new Set([...club.partnerHand, ...club.playerHand]).size === 26);
console.assert(matchesConstraints(club.partnerHand, profile.partnerConstraints, 'C'));
console.assert(matchesConstraints(club.playerHand, profile.playerConstraints, 'C'));
club = applyBid(club, '3D');
console.log(club.auction.at(-1)); // currently 3NT: 1/4 KC; P0425 requires 4C

let minor = createPractice({ profileId: 'minor-d-s-c', seed: 'audit-pass-5' });
minor = applyBid(applyBid(minor, '2H'), '3C');
console.log(minor.auction.at(-1)); // 3NT: 2/5 KC without Q
console.log(availableActions(minor).some(action => action.bid === 'Pass')); // true
console.log(applyBid(minor, 'Pass').contract); // 3NT by North
```

## Recommended decision sequence

1. Correct A1 using the already explicit P0425 rule. Resolve A2's forcing
   interpretation and A3's 16+ scope before changing those meanings.
2. Confirm the missing balanced 3NT exceptions and Horton minimum/continuation
   decisions. These affect ordinary practice, not extreme distributions.
3. Settle R0120 and the grand-try alphabet; retain explicit published practice
   policies for judgemental strength boundaries until a broader model is wanted.
4. Extend the common club/Dappleton/natural routes, then later the unusual shapes.
5. Tie accepted decisions to source fixtures, current tables and a saved-rule
   revision so corrections cannot silently preserve obsolete sessions.
